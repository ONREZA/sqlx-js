# Upgrade to 0.31.0

This guide applies to applications upgrading from `0.30.x`.

This release makes generated PostgreSQL Temporal types follow the runtime
provider bound to each client. It also raises the compiler baseline to
TypeScript 6, the emitted JavaScript baseline to ES2025, cache format to 12,
and generator revision to 30.

## Regenerate committed artifacts

Install TypeScript 6 and run one live prepare against the reviewed schema:

```bash
npm install --save-dev "typescript@>=6 <7"
sqlx-js prepare
```

Old cache entries and declarations fail closed because their Temporal types
were permanently bound to one provider namespace.

## Bind the Temporal provider type

Generated registries now accept the exact provider namespace as their type
parameter. Keep one application-owned registry alias next to the client.

For the recommended adaptive fallback, install `temporal-polyfill`. Its root
entrypoint returns native Temporal when the runtime exposes it and otherwise
uses its local implementation without mutating `globalThis`:

```bash
npm install temporal-polyfill
```

```ts
import { Temporal } from "temporal-polyfill";
import { createSqlClient } from "@onreza/sqlx-js";
import type { SqlxJsGeneratedRegistry as GeneratedRegistry } from "./sqlx-js-env.js";
import queryDescriptors from "./.sqlx-js/runtime-descriptors.json" with { type: "json" };

export type SqlxJsRegistry = GeneratedRegistry<typeof Temporal>;

export const db = createSqlClient<SqlxJsRegistry>(undefined, {
  queryDescriptors,
  temporalApi: Temporal,
});
```

For a runtime with native global Temporal:

```ts
/// <reference lib="esnext.temporal" />

import { createSqlClient } from "@onreza/sqlx-js";
import type { SqlxJsGeneratedRegistry as GeneratedRegistry } from "./sqlx-js-env.js";
import queryDescriptors from "./.sqlx-js/runtime-descriptors.json" with { type: "json" };

export type SqlxJsRegistry = GeneratedRegistry<typeof Temporal>;

export const db = createSqlClient<SqlxJsRegistry>(undefined, {
  queryDescriptors,
  temporalApi: Temporal,
});
```

The native project must include its runtime's Temporal declarations. The
targeted reference above preserves TypeScript's implicit target and DOM libs.
Projects with an explicit `compilerOptions.lib` can instead add
`ESNext.Temporal` alongside the ES2025 base:

```json
{
  "compilerOptions": {
    "target": "ES2025",
    "lib": ["ES2025", "ESNext.Temporal"]
  }
}
```

Fallback projects can keep an explicit base such as `lib: ["ES2025"]` because
`temporal-polyfill` ships provider-local declarations derived from the
TypeScript 6 Temporal contract. Applications that retain another compatible
provider can still bind its exact namespace and pass the same object as
`temporalApi`; it is no longer the recommended scaffold or optional peer.

Profile registries take the provider as their second parameter:

```ts
type ApiRegistry = SqlxJsGeneratedProfileRegistry<"api", typeof Temporal>;
```

Use the application alias in `QueryParams`, `QueryRow`, `QueryResult`, and
`SqlExecutor` helpers so the same provider contract reaches reusable queries.

`temporal-polyfill` is an optional peer. Native-only applications do not need
to install it; fallback applications continue to own and pass it explicitly.
New native-only projects can select the matching scaffold directly:

```bash
sqlx-js init --temporal-provider native
```
