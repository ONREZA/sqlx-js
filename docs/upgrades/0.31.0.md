# Upgrade to 0.31.0

This guide applies to applications upgrading from 0.30.x or earlier.

## Explicit generated registries

The ambient `KnownQueries`, `KnownFileQueries`, `KnownFunctions`, and
`KnownProfiles` interfaces and the process-global managed client exports were
removed. Bind every managed client to its generated registry:

```ts
import { createSqlClient } from "@onreza/sqlx-js";
import type { SqlxJsGeneratedRegistry } from "./sqlx-js-env.js";
import queryDescriptors from "./.sqlx-js/runtime-descriptors.json" with { type: "json" };

export const db = createSqlClient<SqlxJsGeneratedRegistry>(databaseUrl, {
  queryDescriptors,
  temporalApi: Temporal,
});
```

Replace global `sql`, `unsafe`, `ready`, `ping`, `snapshot`, and `close` calls
with the corresponding `db` member. Remove
`configureDefaultTemporalApi(...)`; the provider belongs to each client.
Reusable-query helper types now also require the registry explicitly, for
example `QueryParams<typeof query, SqlxJsGeneratedRegistry>` and
`SqlExecutor<SqlxJsGeneratedRegistry>`.

Profiled clients use the generated helper:

```ts
import type { SqlxJsGeneratedProfileRegistry } from "./sqlx-js-env.js";

const api = createSqlClient<SqlxJsGeneratedProfileRegistry<"api">>(databaseUrl, {
  execution: "adaptive",
  profile: { name: "api", role: "app_api" },
});
```

## One column assertion map

Move every `jsonbTypes` entry into `columnTypes`. `columnTypes` now owns direct
scalar, JSON/JSONB, JSON-backed domain, and JSON/JSONB-array assertions. JSON
values still use the `SqlxJson<T>` runtime boundary. Non-JSON PostgreSQL arrays
remain database-typed and use `arrayElementNullability` only for an externally
enforced element invariant.

## Embedded SQL is a prepare artifact

Replace `sqlx-js queries --embed <path>` with configuration:

```ts
export default defineConfig({
  sqlFiles: { output: "src/sql-files.generated.ts" },
});
```

Live prepare publishes that module atomically with declarations, descriptors,
enum output, and cache. Offline prepare regenerates it, and verify compares it.
The `queries` command is now read-only.

## Unified lifecycle observer

Replace `onQueryStart`, `onQueryTimeout`, `onQueryError`, and
`onClientStateChange` with one discriminated observer:

```ts
onLifecycle(event) {
  switch (event.kind) {
    case "query-start":
    case "query-timeout":
    case "query-error":
    case "state-change":
      observe(event);
  }
}
```

`onQuery`, `onQueryHookError`, and `onLifecycleHookError` retain their existing
roles.

## Regeneration and verification

The cache format is 11 and the generator revision is 28. Regenerate every
project from the schema authority; old artifacts fail closed.

```bash
sqlx-js dev --strict-inference
sqlx-js verify --strict-inference
tsc --noEmit
```

For a query-only project, run live `sqlx-js prepare --strict-inference` instead
of `dev`. Roll back application code and all generated artifacts together if
the package version is rolled back.
