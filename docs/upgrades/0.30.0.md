# Upgrade to 0.30.0

This guide applies to applications upgrading from `0.29.x`.

This release replaces the JavaScript `Date` SQL boundary with Temporal, makes
`timestamp without time zone` an explicit query policy, and rejects JSON
integers that JavaScript cannot represent exactly.

## Install the Temporal provider

The current supported runtimes do not expose a compatible global Temporal API
by default. Install the peer provider and keep TypeScript on 5.4–5.9 while the
official polyfill and TypeScript 6 draft declarations remain incompatible:

```bash
npm install @js-temporal/polyfill
npm install --save-dev "typescript@>=5.4 <6"
```

Pass the provider at the application client boundary:

```ts
import { Temporal } from "@js-temporal/polyfill";

export const db = createSqlClient<SqlxJsGeneratedRegistry>(undefined, {
  queryDescriptors,
  temporalApi: Temporal,
});
```

sqlx-js does not attach a polyfill to `globalThis`. If a future runtime exposes
a compatible native `globalThis.Temporal`, `temporalApi` can be omitted.

Applications temporarily retaining the deprecated global exports must configure
their process-wide provider before the first global query or lifecycle call:

```ts
import { configureDefaultTemporalApi } from "@onreza/sqlx-js";
import { Temporal } from "@js-temporal/polyfill";

configureDefaultTemporalApi(Temporal);
```

## Replace Date SQL values

Generated contracts now use these exact types:

| PostgreSQL | Previous | Current |
| --- | --- | --- |
| `date` | `PgTemporal` or `Date` | `Temporal.PlainDate` |
| `time` | `string` | `Temporal.PlainTime` |
| `timestamp` | `PgTemporal` or `Date` | `Temporal.PlainDateTime` |
| `timestamptz` | `PgTemporal` or `Date` | `Temporal.Instant` |

Replace `new Date(...)` parameters with the matching Temporal constructor.
Do not convert a wall-clock `timestamp` to an instant by appending `Z`; decide
whether the database value is a civil time or whether the column should migrate
to `timestamptz`. Temporal infinity is no longer exposed and fails explicitly.

The codec preserves microseconds returned by PostgreSQL; declared typmods such
as `timestamp(3)` still apply their server-owned precision. Inputs with
sub-microsecond precision now fail instead of being rounded. PostgreSQL `time`
24:00 also fails because `Temporal.PlainTime` has no exact representation.
`timetz` and `interval` remain strings because there is no faithful direct
Temporal representation for their PostgreSQL semantics. Leap-second values
also fail because Temporal would silently normalize `:60` to `:59`.

## Review timestamp without time zone queries

The default policy rejects every direct parameter/result and every physical
column mapped to a parameter that contains `timestamp without time zone`,
including arrays, domains, ranges, multiranges, and composites. For an
intentional civil-time query, add a named, source-local exception:

```ts
export const storeOpening = defineQuery.execute(
  "schedule.storeOpening",
  "INSERT INTO store_schedule (opens_at) VALUES ($1::timestamp)",
  {
    temporal: {
      timestampWithoutTimeZone: {
        allow: true,
        reason: "Opening time is local civil time, not an instant",
      },
    },
  },
);
```

For a project that predominantly stores civil times, set
`temporal.timestampWithoutTimeZone: "allow"` in config and use the local
`"reject"` override where an instant is required. Every PostgreSQL session is
pinned to UTC independently of this query policy. A later SQL or function
attempt to change `TimeZone` away from UTC or `DateStyle` away from ISO fails
closed and discards the affected connection.

## Review JSON integers

`sql.json(...)` and `json`/`jsonb` result decoding reject non-finite numbers and
integers outside `Number.MIN_SAFE_INTEGER` through `Number.MAX_SAFE_INTEGER`.
Encode larger exact integers as JSON strings or store them in a PostgreSQL
`numeric`/integer column with the appropriate codec.

JSON parameters are also restricted to deterministic plain records and arrays.
Replace class instances, custom `toJSON`, accessors, binary views, array holes,
and ignored symbol/named properties with an explicit plain JSON representation.

## Regenerate artifacts

The query cache is now format 8, the declaration generator is revision 25,
and runtime descriptors use format 3. Run a live prepare and commit the complete
replacement:

```bash
sqlx-js prepare
sqlx-js prepare --check
tsc --noEmit
```

Do not hand-edit `PgTemporal` references in generated declarations. A live
prepare derives the new Temporal types and timestamp policy facts from
PostgreSQL.

## Rollback

Restore version 0.29.x and its matching generated artifacts together. Do not
ask the older CLI to read or rewrite format-8 query caches or format-3 runtime
descriptors.
