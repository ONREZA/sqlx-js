# Upgrade to 0.33.0

This guide applies to applications upgrading from `0.32.x`.

Named parameter objects now use the same exact-key contract at compile time
that the runtime already enforced. The release also reserves `$__proto__` and
raises the cache format to 13.

## Map wider application inputs

Variables whose static type exposes fields outside the generated query
contract are no longer accepted directly. Map the application input at the
query boundary:

```ts
type UpdateUserInput = {
  id: string;
  email: string;
  auditReason: string;
};

declare const input: UpdateUserInput;

await sql(
  `UPDATE users SET email = $email WHERE id = $id`,
  { id: input.id, email: input.email },
);
```

This applies to root, transaction, savepoint, cardinality, `with`, SQL-file,
and `defineQuery.run` / `runWith` execution. Positional query arguments are
unchanged.

## Rename `$__proto__`

JavaScript object-literal syntax treats `__proto__` as a prototype setter
instead of an ordinary own data property. Rename that placeholder in both the
SQL and parameter object before regenerating artifacts:

```ts
await sql(
  `SELECT $prototype_value::text`,
  { prototype_value: value },
);
```

Committed caches containing `$__proto__` cannot be regenerated without this
source change. The CLI reports the reserved name and the required rename.

## Regenerate committed artifacts

After source migration, run one live prepare against the reviewed schema:

```bash
sqlx-js prepare
sqlx-js prepare --check
tsc --noEmit
```

Commit `.sqlx-js/`, `sqlx-js-env.d.ts`, and configured generated outputs
together. The cache-format fence rejects older manifests and runtime
descriptors instead of mixing contracts.

## Rollback

Restore version `0.32.x`, the previous source parameter names, and its matching
generated artifacts together. Do not ask the older CLI to consume or rewrite
format-13 cache artifacts.
