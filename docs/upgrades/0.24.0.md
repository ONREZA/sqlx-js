# Upgrade to 0.24.0 or 0.24.1

This guide applies to applications upgrading from `0.23.x`. The temporal
contract was introduced in 0.24.0. Version 0.24.1 only adjusts the TLS
restart-rejection CI smoke and adds no application, generated-type, cache, or
runtime migration.

## Regenerate generated artifacts

The generator revision is now 22 and the runtime descriptor format is now 2.
The configured temporal policy is part of the type-affecting config hash and
is stored in generated registries and runtime descriptors. Run a live prepare
against the intended PostgreSQL schema; offline regeneration cannot convert
the older descriptor format:

```bash
sqlx-js prepare
sqlx-js prepare --check --strict-inference
sqlx-js prepare --verify --strict-inference
tsc --noEmit
```

Commit the query cache, cache manifest, runtime descriptor, generated
declarations, and any generated enum module together.

## Choose the temporal infinity contract

PostgreSQL `date`, `timestamp`, and `timestamptz` accept `infinity` and
`-infinity`, while JavaScript `Date` does not. The default remains the
lossless contract:

```ts
export default defineConfig({
  temporal: {
    infinity: "preserve",
  },
});
```

Prepare generates `PgTemporal`, defined as
`Date | "infinity" | "-infinity"`, for scalar temporal values and uses the
same union for temporal array elements.

If the application invariant prohibits infinity, select the fail-closed
contract:

```ts
export default defineConfig({
  temporal: {
    infinity: "reject",
  },
});
```

Prepare then generates `Date` for temporal values. The matching runtime rejects
infinite results during decoding and infinite parameters during encoding
instead of allowing the generated type and runtime value domain to diverge.
Review application code that narrows `PgTemporal`, serializes the string
literals, or accepts temporal arrays before switching to `reject`.

## Bind the same policy at runtime

A descriptor-bound generated client adopts the policy from the generated
runtime descriptor:

```ts
import { createSqlClient } from "@onreza/sqlx-js";
import type { SqlxJsGeneratedRegistry } from "./sqlx-js-env.js";
import queryDescriptors from "./.sqlx-js/runtime-descriptors.json" with { type: "json" };

export const db = createSqlClient<SqlxJsGeneratedRegistry>(undefined, {
  queryDescriptors,
});
```

An adaptive managed client or raw client cannot obtain the policy from a
descriptor. With a generated `reject` registry it must declare the matching
policy explicitly:

```ts
export const adaptive = createSqlClient<SqlxJsGeneratedRegistry>(undefined, {
  execution: "adaptive",
  temporal: { infinity: "reject" },
});
```

The generated registry makes a mismatched policy a type error, and managed
descriptor loading also rejects a runtime mismatch. The deprecated global
`sql` and SQL-file module augmentation is not emitted for `reject`, because a
global API cannot bind one project-owned runtime policy. Move those calls to a
generated `createSqlClient` before enabling `reject`.

## Review fail-closed TLS behavior

`sslmode=require`, `verify-ca`, and `verify-full` no longer continue after a
rejected, malformed, stalled, closed, or certificate-invalid TLS negotiation.
Only `prefer` may fall back to plaintext, and only when PostgreSQL explicitly
reports that TLS is unavailable. PostgreSQL startup, authentication, codec
discovery, and application SQL are not dispatched before required TLS
succeeds.

Exercise startup and replacement connections against the production endpoint
or pooler. For `verify-ca`, provide the intended CA chain. For `verify-full`,
also ensure that the connection host matches the certificate DNS name or IP
address. Do not change to `prefer` or disable verification to make a failed
upgrade pass; correct the endpoint, certificate chain, or connection URL.

## Update Node ESM config imports

Node 24 requires file extensions on local ESM imports from
`sqlx-js.config.ts`:

```ts
import { databaseProfiles } from "./src/database-profiles.ts";
```

The CLI now reports an actionable error when an extensionless local import
resolves to an existing TypeScript or JavaScript file. Projects intentionally
using Bun-only extensionless resolution can invoke the CLI through
`bun --bun sqlx-js`, but portable configs should use explicit extensions.

## Optional runtime failure observation

Managed clients now accept `onQueryError`. It reports the stable query
metadata, generation, failure phase, outcome, and a redacted error summary.
PostgreSQL failures include safe server fields such as SQLSTATE; lifecycle
events never include SQL text, parameters, connection URLs, credentials, or
certificate objects. Existing observers require no change, but applications
that need failure metrics can adopt this hook instead of inferring failures
from timeout or completion callbacks.

## Rollout and rollback

Deploy application code, generated declarations, cache artifacts, and runtime
descriptors from the same revision. Do not deploy `reject` until existing data
and write paths are known not to contain or send temporal infinity.

Rollback requires restoring the complete 0.23.x application and generated
artifact set. A 0.23.x runtime cannot consume descriptor format 2, and mixing a
0.24.x declaration generated under one temporal policy with a runtime using
the other policy breaks the reviewed type/value contract.
