# Upgrade to 0.25.0

This guide applies to applications upgrading from `0.24.x`. Version 0.25.0
changes human CLI output and doctor diagnostics. It does not change the cache
format, generator revision, runtime descriptor format, generated TypeScript
contracts, or query runtime.

## Choose the required prepare detail level

`prepare`, `prepare --check`, `prepare --offline`, and `prepare --verify` now
use compact human output by default. The summary reports source sites, unique
query contracts, functions, enums, and warning/error counts grouped by phase.
Errors remain expanded, while per-query success lines and warning details are
omitted.

Use the new detail flags when investigating a run:

```bash
# Compact counts and full warning details
sqlx-js prepare --warnings

# Full warning details and per-query progress
sqlx-js prepare --verbose
```

The summary prints hints for both modes when they are relevant. `--warnings`
and `--verbose` are mutually exclusive and cannot be combined with `--json` or
`--jsonl`. Watch mode remains streaming and does not accept either flag.

Automation that consumes `prepare --json` or `prepare --watch --jsonl` requires
no output migration. Exit codes and artifact writes are unchanged.

## Review doctor schema ownership

Doctor no longer treats an absent `schema.provider` as declared ownership by
the built-in migration provider. It now distinguishes:

- the explicitly configured provider;
- declared DDL ownership;
- the effective provider used by `dev` and `verify`.

When `schema.provider` is absent, DDL ownership is reported as external or
unspecified, while the effective `dev`/`verify` default remains `builtin`.
Projects that want sqlx-js to own the schema workflow should configure
`schema.provider: "builtin"` or `"pgschema"` explicitly.

## Interpret descriptor coverage counters

Descriptor coverage now labels its denominator as unique SQL
fingerprint/connection-profile contracts. Source-level counters use different
units:

- `parameterized`, `definitions`, and `executionSites` count source sites;
- `queryContracts`, `descriptor`, and `missing` count unique query/profile
  contracts;
- `descriptorConfigured`, `adaptive`, and `unknown` count direct execution
  sites.

Doctor JSON includes a `countSemantics` object that records these units. Tools
should use it instead of assuming that `parameterized`, `queryContracts`, and
`descriptor` have equal totals.

## Verify the upgrade

No artifact regeneration is required solely for this upgrade. Run the normal
project gates:

```bash
sqlx-js prepare --check --strict-inference
sqlx-js doctor
tsc --noEmit
```

If CI parses human-readable prepare or doctor text, migrate it to the versioned
JSON output instead of matching the new summaries.

Rollback only requires restoring the previous CLI package. Generated artifacts
remain compatible because their format revisions do not change in 0.25.0.
