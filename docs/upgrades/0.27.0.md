# Upgrade to 0.27.0

This guide applies to applications upgrading from `0.26.x`. Version 0.27.0
adds source-owned query validation contracts, fail-closed CLI package identity,
and complete PostgreSQL function settings inventory. It changes committed query,
function, declaration-generator, and schema-snapshot formats.

## Regenerate live artifacts

The query cache is now format 6, the declaration generator is revision 23, the
function catalog is format 3, and the schema snapshot is format 3. Old formats
fail closed with regeneration guidance. `prepare --offline` cannot upgrade
facts that must come from PostgreSQL.

Run against the canonical development or shadow schema:

```bash
sqlx-js prepare
sqlx-js snapshot dump # when the project commits a schema snapshot
sqlx-js prepare --check --strict-inference
sqlx-js snapshot check # when applicable
tsc --noEmit
```

Commit the regenerated `.sqlx-js/`, `sqlx-js-env.d.ts`, and schema snapshot
artifacts together.

## Replace nullable sentinels with source contracts

PostgreSQL has no per-function-argument `NOT NULL` catalog flag. When a direct
function call accepts null but the surrounding SQL does not otherwise express
that fact, declare it once on the reusable query:

```ts
export const retire = defineQuery.one(
  "billing.retire",
  `SELECT retire_subscription($retireAt::timestamptz, $operationId::text)`,
  { nullableParams: ["retireAt", "operationId"] },
);
```

Use 1-based numbers for positional parameters. Live prepare rejects an
annotation that would feed null directly into a `NOT NULL` stored target.
Remove sentinel encodings only after the generated call contract is
`Date | null` / `string | null` and runtime smoke tests cover actual SQL null.

`KnownFunctions` now includes `language`, `strict`, and every function-local
`settings` entry. Its input parameter types include SQL `null` because even a
`STRICT` PostgreSQL function accepts null inputs; strictness controls body
execution, not call validity.

## Acknowledge intentional parse-only statements

Utility statements outside PostgreSQL's generic planning surface can record a
reviewed expectation:

```ts
export const analyze = defineQuery.execute(
  "maintenance.analyze",
  `ANALYZE billing_event`,
  { expectedValidation: "parse-only" },
);
```

Parse and Describe validation remain active. Prepare warns if the statement
later becomes plannable or if another call site for the same query/profile has
not acknowledged the weaker validation boundary. `--strict-inference` rejects
unacknowledged parse-only statements.

## Run the CLI resolved for the project root

Project commands now compare the running CLI version with
`@onreza/sqlx-js` resolved from `--root`. A mismatch exits before scanning,
artifact writes, or database changes, including `init`. Use the package-local
script in monorepos. Read-only `sqlx-js doctor --json` reports both real package
paths and versions; `doctor --fix` refuses to write while they mismatch.

## Review function settings and PL/pgSQL coverage

Function caches and schema snapshots now preserve the complete normalized
`pg_proc.proconfig` array rather than only `search_path`. This makes settings
such as `TimeZone` visible to `prepare --verify` and `snapshot check`.

The managed pgschema 1.12.0 provider does not preserve function-local `SET`
clauses other than `search_path`; see
[pgplex/pgschema#526](https://github.com/pgplex/pgschema/issues/526). Keep such
routines on another DDL workflow until a fixed provider version is pinned.

Function `language` is inventory only. PostgreSQL can defer parsing PL/pgSQL
statements until execution, so add execution smoke tests for changed function
paths or run `plpgsql_check` in a separately configured validation database.
Prepare never executes application queries.

## Rollback

Restore the previous package and its matching generated artifacts together.
Do not ask an older CLI to read or rewrite format-6 query caches, format-3
function catalogs, or format-3 schema snapshots.
