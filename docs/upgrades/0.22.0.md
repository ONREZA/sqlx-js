# Upgrade to 0.22.0

This guide applies when upgrading from `0.21.x`.

## Regenerate query artifacts

The cache format and generator revision changed to add stable parameter type
identities and the derived `.sqlx-js/runtime-descriptors.json` artifact.
Regenerate against the development database and commit the complete result:

```bash
sqlx-js prepare
git add .sqlx-js sqlx-js-env.d.ts
```

Older cache entries fail with an actionable regeneration error. Do not copy
`runtime-descriptors.json` between projects or generate it independently from
the per-query cache.

## Enable the optional runtime fast path

Existing applications keep the adaptive parameter-description path until they
pass the generated JSON explicitly:

```ts
import { createSqlClient } from "@onreza/sqlx-js";
import queryDescriptors from "./.sqlx-js/runtime-descriptors.json" with { type: "json" };

export const db = createSqlClient(process.env.DATABASE_URL, {
  queryDescriptors,
});
```

For connection profiles, use the same artifact and continue passing the exact
generated profile. Missing query entries fall back to adaptive execution;
incompatible artifacts, profile roles, and database-local type identities fail
before application SQL dispatch.

## Verify before rollout

```bash
sqlx-js prepare --check
sqlx-js prepare --verify
tsc --noEmit
bun test --timeout 120000
```

Deploy schema changes with their normal backward-compatible rollout before
application instances that depend on them. Rollback remains the previous
application build together with its own generated artifacts.
